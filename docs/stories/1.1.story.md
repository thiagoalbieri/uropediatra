## Descrição

Como usuário que depende de tecnologia assistiva (leitor de tela, navegação por teclado), preciso que o site da Dra. Marcela seja operável sem mouse e com identificação correta de todos os controles interativos, para que eu possa agendar uma consulta de forma independente.

## Contexto

O site falha em 4 critérios WCAG AA obrigatórios:
- **WCAG 4.1.2** — Botão WhatsApp float sem nome acessível (`aria-label`)
- **WCAG 4.1.2** — Hamburger menu sem estado (`aria-expanded`)
- **WCAG 2.4.1** — Sem skip-to-content (navegação por teclado presa no header)
- **WCAG 2.4.7** — Focus ring visível depende apenas do padrão do browser

## Critérios de Aceitação

**UX-06 — WhatsApp float:**
- [ ] Botão SP tem `aria-label="Agendar consulta — São Paulo"`
- [ ] Botão Jundiaí tem `aria-label="Agendar consulta — Jundiaí"`
- [ ] Labels testados com leitor de tela (VoiceOver/NVDA)

**UX-07 — Hamburger menu:**
- [ ] Hamburger tem `aria-expanded="false"` no estado fechado
- [ ] `aria-expanded` alterna para `"true"` quando menu abre
- [ ] Alternância acontece via `main.js` (toggle existente)

**UX-08 — Skip-to-content:**
- [ ] Link `<a href="#main-content">Ir para o conteúdo</a>` presente no início do `<body>` em todas as 18 páginas
- [ ] Link visível apenas no foco (`:focus-visible`)
- [ ] Elemento `<main>` tem `id="main-content"` em todas as páginas

**UX-13 — Focus visible:**
- [ ] CSS define `:focus-visible` com outline visível usando `--azul` (#1A6FA3)
- [ ] Outline tem mínimo 2px de largura e contraste >= 3:1 (WCAG 2.4.11)
- [ ] Aplicado a todos os elementos interativos (a, button, input, select, textarea)

## Arquivos a Modificar

- `index.html` e todas as 18 páginas HTML — skip-to-content, aria-label, aria-expanded, id="main-content"
- `css/style.css` — regra `:focus-visible`
- `js/main.js` — toggle de `aria-expanded` no hamburger

## Escopo

**IN:** Adicionar atributos ARIA, skip link e estilos de foco  
**OUT:** Redesign de componentes, mudanças de layout, outros critérios WCAG além dos 4 listados
