# Story 4.1 — Migração para Eleventy (SSG)

**Epic:** UROPEDIATRA-DEBT  
**Sprint:** 4+ (backlog estrutural)  
**Status:** Ready  
**Prioridade:** P3 — Dívida estrutural  
**Esforço estimado:** 12–20 horas  
**Débitos:** SYS-08 (deduplicação header/footer), SYS-07 (CSS modular)

---

## Descrição

Como desenvolvedor responsável pelo site, preciso eliminar a duplicação de header, footer e botão WhatsApp em 18 arquivos HTML, para que qualquer alteração nesses componentes seja feita uma única vez e propagada automaticamente para todas as páginas.

## Contexto

Atualmente cada edição no header ou footer requer 18 alterações manuais síncronas. Uma mudança perdida gera inconsistência visível para o paciente. A migração para Eleventy (11ty) resolve isso com templates Nunjucks — o output continua sendo HTML estático compatível com GitHub Pages, mas o código fonte usa templates reutilizáveis.

## Critérios de Aceitação

**Setup do projeto 11ty:**
- [ ] `package.json` criado com `@11ty/eleventy` como devDependency
- [ ] `.eleventy.js` configurado com diretório de input (`src/`) e output (`docs/` ou `_site/`)
- [ ] GitHub Actions configurado para build automático via `npx @11ty/eleventy` no push

**Templates Nunjucks:**
- [ ] `src/_includes/base.njk` — layout base com `<head>`, header, footer, whatsapp-float
- [ ] `src/_includes/header.njk` — componente header extraído
- [ ] `src/_includes/footer.njk` — componente footer extraído
- [ ] `src/_includes/whatsapp-float.njk` — componente float extraído

**Migração de conteúdo:**
- [ ] Todas as 18 páginas migradas para arquivos `.njk` em `src/`
- [ ] Páginas de tratamento em `src/tratamentos/`
- [ ] Front matter YAML com `title`, `description`, `canonical` em cada página
- [ ] Output gerado idêntico ao HTML original (zero regressão visual)

**CSS modular (aproveitando a migração):**
- [ ] `css/style.css` quebrado em módulos: `base.css`, `components/header.css`, `components/footer.css`, etc.
- [ ] Import centralizado no `base.njk`
- [ ] Zero inline styles remanescentes (coordenar com Story 2.4)

**CI/CD:**
- [ ] `.github/workflows/build.yml` criado
- [ ] Build roda em cada push para main
- [ ] GitHub Pages serve o output gerado

## Arquivos a Criar
